# Лабораторная работа №3 — «Лента»

Простое веб-приложение на **React** с данными [JSONPlaceholder](https://jsonplaceholder.typicode.com/). Для HTTP-запросов используется **Axios**, для сборки и запуска — **Vite**. Серверная часть, регистрация и ключ API не нужны.

## Возможности

- Загрузка 100 постов и списка авторов при открытии страницы.
- Поиск по заголовку и тексту, фильтр по автору.
- Вывод по 10 постов на странице.
- Создание поста через форму и удаление любого поста.
- Отдельный просмотр добавленных в этой сессии постов.
- Проверка пустых полей, сообщения об ошибках, повтор загрузки.
- Адаптивный интерфейс на русском языке.

**Особенность API:** JSONPlaceholder имитирует создание и удаление. Изменения хранятся в состоянии React до перезагрузки страницы. После перезагрузки снова загружается исходный список. Новые посты создаются от имени пользователя №1 (Leanne Graham). Это учебный пример без авторизации.

## Запуск

Нужны Node.js **20.19+ в ветке 20 или 22.12+** и доступ к интернету.

Откройте терминал в папке `lab3`:

```powershell
npm.cmd ci
npm.cmd run dev
```

Перейдите по адресу, который напечатает Vite, обычно **http://127.0.0.1:5173**.

В PowerShell `npm.cmd` позволяет выполнить команды без изменения политики запуска скриптов. В других оболочках можно использовать `npm`.

## Сборка

```powershell
npm.cmd run build
npm.cmd run preview
```

Сборка находится в `dist/`. `preview` обычно открывает её по адресу **http://127.0.0.1:4173**. Открывать `index.html` двойным щелчком не нужно: используйте сервер Vite или любой статический HTTP-сервер для `dist/`.

## Использование API

В `api/client.js` создаётся экземпляр Axios с базовым адресом `https://jsonplaceholder.typicode.com` и таймаутом 15 секунд. Хук `usePosts` вызывает методы `get`, `post` и `delete`, а данные берёт из `response.data`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/posts` | Загрузка постов |
| GET | `/users` | Загрузка авторов |
| POST | `/posts` | Создание поста |
| DELETE | `/posts/{id}` | Удаление поста |

Пример тела POST-запроса:

```json
{
  "title": "Мой первый пост",
  "body": "Приложение работает на React!",
  "userId": 1
}
```

Поиск, фильтрация и переключение страниц выполняются в браузере по загруженному списку.

## Как работает React

1. `main.jsx` создаёт корень через `createRoot` и отображает `FeedPage`.
2. Хук `usePosts` загружает данные в `useEffect`. При размонтировании незавершённые запросы отменяются через `AbortController`.
3. `useState` хранит посты, авторов, значения формы, фильтры и состояние запросов. JSX описывает интерфейс на основе этих данных.
4. `PostForm` получает функцию `onAdd` через props. При отправке формы вызывается POST-запрос. После успешного ответа новый пост добавляется в начало массива, форма очищается, фильтры сбрасываются, чтобы пост был виден.
5. `PostItem` получает данные и функцию удаления через props. Пост исчезает из массива только после успешного DELETE-запроса. При ошибке он остаётся на экране и кнопку можно нажать повторно.
6. React обновляет DOM при изменении состояния. Ручное изменение HTML не используется, текст выводится с экранированием.

JSONPlaceholder возвращает одинаковый `id = 101` для нескольких новых постов. Поэтому у каждого поста есть отдельный `key`: для загруженных записей он основан на ID, для новых создаётся через `crypto.randomUUID()`. Удаление одного добавленного поста не затрагивает другой с таким же ID API.

В режиме разработки `StrictMode` может запускать эффект загрузки дважды. Это штатное поведение React: первый запрос отменяется при очистке эффекта.

## Проверка вручную

1. Откройте приложение: должны загрузиться 100 постов, по 10 на странице.
2. Введите часть заголовка в поиск, выберите автора и переключите страницу.
3. Добавьте два поста. Оба должны появиться в ленте и в разделе «Мои добавленные».
4. Удалите один из них: второй должен остаться.
5. Попробуйте отправить поля из пробелов: приложение покажет ошибку.
6. Перезагрузите страницу: восстановится исходный список API.
7. Отключите сеть и перезагрузите страницу: появится сообщение и кнопка повтора. После восстановления сети нажмите «Попробовать снова».
